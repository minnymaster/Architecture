# Лабораторная работа №4. Проектирование REST API

---

## 1. Проектные решения

### 1.1 Ресурсо-ориентированный дизайн
**Решение:** Использовать ресурсо-ориентированный подход для проектирования API.

**Описание:**
- Каждый тип данных (тесты, вопросы, результаты) представлен как отдельный ресурс.
- Используются существительные во множественном числе для обозначения ресурсов.

**Пример:**
- `/tests` — для работы со списком тестов.
- `/tests/{id}/questions` — для работы с вопросами конкретного теста.

**Обоснование:** Такой подход делает API интуитивно понятным и соответствует REST-стандартам.


### 1.2 Использование стандартных HTTP-методов
**Решение:** Использовать стандартные HTTP-методы для выполнения CRUD-операций.

| Метод   | Описание                                                                 |
|---------|--------------------------------------------------------------------------|
| GET     | Получение данных (например, списка тестов или конкретного теста).       |
| POST    | Создание новых данных (например, создание теста или отправка ответов). |
| PUT     | Полное обновление существующих данных (например, редактирование теста).|
| DELETE  | Удаление данных (например, удаление теста).                             |

**Обоснование:** Стандартные методы обеспечивают предсказуемость и совместимость с большинством клиентов и серверов.


### 1.3 Версионирование через URL
**Решение:** Использовать версионирование API через префикс в URL.

**Описание:**
- Версия API указывается в пути URL.
- Пример: `/api/v1/tests`.

**Обоснование:** Позволяет поддерживать несколько версий API одновременно, обеспечивая обратную совместимость.


### 1.4 Использование JSON
**Решение:** Использовать JSON для обмена данными между клиентом и сервером.

**Описание:**
- Все запросы и ответы используют формат JSON.
- Заголовок `Content-Type: application/json` обязателен для всех запросов и ответов.

**Обоснование:** JSON является стандартным форматом для REST API, он легко читается и обрабатывается.




### 1.6 Стандартизированные сообщения об ошибках
**Решение:** Использовать стандартный формат для сообщений об ошибках.

**Описание:**
- Все ошибки возвращаются в формате JSON.
- Структура ошибки включает код ошибки, сообщение и дополнительные данные.

**Пример:**
```json
{
  "error": {
    "code": 404,
    "message": "Тест не найден",
    "details": "Тест с ID 123 не существует."
  }
}

```


## 2. Реализация API

### 1. Получение списка тестов

**Метод:** `GET`

**Эндпоинт:** `/api/v1/tests`

**Описание:** Возвращает список всех доступных тестов.

**Параметры запроса:** Нет.

**Формат ответа:** JSON

**Пример ответа:**
```json
{
  "status": "success",
  "data": [
    {
      "id": 1,
      "title": "Тест по SAP BW",
      "description": "Тест на знание основ SAP BW",
      "category": "SAP BW"
    },
    {
      "id": 2,
      "title": "Тест по ETL",
      "description": "Тест на знание процессов ETL",
      "category": "ETL"
    }
  ]
}
```


### 2. Получение информации о конкретном тесте

**Метод:** `GET`

**Эндпоинт:** `/api/v1/tests/{id}`

**Описание:** Возвращает информацию о конкретном тесте по его идентификатору.

**Параметры запроса:**
- `id` (обязательный, integer) — идентификатор теста.

**Формат ответа:** JSON

**Пример ответа:**
```json
{
  "status": "success",
  "data": {
    "id": 1,
    "title": "Тест по SAP BW",
    "description": "Тест на знание основ SAP BW",
    "category": "SAP BW"
  }
}
```

**Ошибки:**
- `404 Not Found` — если тест не найден.

**Пример ошибки:**
```json
{
  "status": "error",
  "error": {
    "code": 404,
    "message": "Тест не найден",
    "details": "Тест с ID 123 не существует."
  }
}
```


### 3. Создание нового теста

**Метод:** `POST`

**Эндпоинт:** `/api/v1/tests`

**Описание:** Создает новый тест.

**Параметры запроса (в теле запроса):**
- `title` (обязательный, string) — название теста.
- `description` (обязательный, string) — описание теста.
- `category` (обязательный, string) — категория теста.

**Формат запроса:** JSON

**Пример запроса:**
```json
{
  "title": "Тест по SAP HANA",
  "description": "Тест на знание основ SAP HANA",
  "category": "SAP HANA"
}
```

**Формат ответа:** JSON

**Пример ответа:**
```json
{
  "status": "success",
  "data": {
    "id": 3,
    "title": "Тест по SAP HANA",
    "description": "Тест на знание основ SAP HANA",
    "category": "SAP HANA"
  }
}
```

**Ошибки:**
- `400 Bad Request` — если отсутствуют обязательные поля.

**Пример ошибки:**
```json
{
  "status": "error",
  "error": {
    "code": 400,
    "message": "Некорректные данные",
    "details": "Отсутствуют обязательные поля: title."
  }
}
```


### 4. Получение списка вопросов для теста

**Метод:** `GET`

**Эндпоинт:** `/api/v1/tests/{id}/questions`

**Описание:** Возвращает список вопросов для конкретного теста.

**Параметры запроса:**
- `id` (обязательный, integer) — идентификатор теста.

**Формат ответа:** JSON

**Пример ответа:**
```json
{
  "status": "success",
  "data": [
    {
      "id": 1,
      "text": "Что такое InfoCube?",
      "type": "open"
    },
    {
      "id": 2,
      "text": "Какие типы данных используются в SAP BW?",
      "type": "multiple-choice",
      "options": ["Master Data", "Transaction Data", "Metadata", "All of the above"]
    }
  ]
}
```

**Ошибки:**
- `404 Not Found` — если тест не найден.


### 5. Отправка ответов на тест

**Метод:** `POST`

**Эндпоинт:** `/api/v1/tests/{id}/submit`

**Описание:** Принимает ответы пользователя на вопросы теста и сохраняет их для дальнейшей обработки.

**Параметры запроса:**
- `id` (обязательный, integer) — идентификатор теста.

**Формат запроса:** JSON

**Пример запроса:**
```json
{
  "answers": [
    {
      "question_id": 1,
      "answer": "InfoCube — это многомерная структура данных в SAP BW."
    },
    {
      "question_id": 2,
      "answer": ["Master Data", "Transaction Data"]
    }
  ]
}
```

**Формат ответа:** JSON

**Пример ответа:**
```json
{
  "status": "success",
  "message": "Ответы успешно сохранены"
}
```

**Ошибки:**
- `400 Bad Request` — если поле `answers` отсутствует или не является массивом.
- `404 Not Found` — если тест не найден.

**Пример ошибки:**
```json
{
  "status": "error",
  "error": {
    "code": 400,
    "message": "Некорректные данные",
    "details": "Поле answers должно быть массивом."
  }
}
```


### 6. Получение результатов теста

**Метод:** `GET`

**Эндпоинт:** `/api/v1/tests/{id}/results`

**Описание:** Возвращает результаты прохождения теста для конкретного пользователя.

**Параметры запроса:**
- `id` (обязательный, integer) — идентификатор теста.

**Формат ответа:** JSON

**Пример ответа:**
```json
{
  "status": "success",
  "data": {
    "results": [
      {
        "question_id": 1,
        "score": 5,
        "feedback": "Отличный ответ!"
      },
      {
        "question_id": 2,
        "score": 3,
        "feedback": "Не совсем точно, попробуйте еще раз."
      }
    ],
    "total_score": 8
  }
}
```

**Ошибки:**
- `404 Not Found` — если тест не найден.


### 7. Создание нового вопроса для теста

**Метод:** `POST`

**Эндпоинт:** `/api/v1/tests/{id}/questions`

**Описание:** Добавляет новый вопрос к тесту.

**Параметры запроса:**
- `id` (обязательный, integer) — идентификатор теста.

**Формат запроса:** JSON

**Пример запроса:**
```json
{
  "text": "Что такое DSO?",
  "type": "open"
}
```

**Формат ответа:** JSON

**Пример ответа:**
```json
{
  "status": "success",
  "data": {
    "id": 3,
    "text": "Что такое DSO?",
    "type": "open"
  }
}
```

**Ошибки:**
- `400 Bad Request` — если отсутствуют обязательные поля.
- `404 Not Found` — если тест не найден.


### 8. Обновление теста

**Метод:** `PUT`

**Эндпоинт:** `/api/v1/tests/{id}`

**Описание:** Обновляет информацию о тесте.

**Параметры запроса:**
- `id` (обязательный, integer) — идентификатор теста.

**Параметры запроса (в теле запроса):**
- `title` (необязательный, string) — новое название теста.
- `description` (необязательный, string) — новое описание теста.
- `category` (необязательный, string) — новая категория теста.

**Формат ответа:** JSON

**Пример ответа:**
```json
{
  "status": "success",
  "data": {
    "id": 1,
    "title": "Обновленный тест по SAP BW",
    "description": "Обновленное описание теста на знание основ SAP BW",
    "category": "SAP BW"
  }
}
```

**Ошибки:**
- `400 Bad Request` — если отсутствуют данные для обновления.
- `404 Not Found` — если тест не найден.


### 9. Удаление теста

**Метод:** `DELETE`

**Эндпоинт:** `/api/v1/tests/{id}`

**Описание:** Удаляет тест по его идентификатору.

**Параметры запроса:**
- `id` (обязательный, integer) — идентификатор теста.

**Формат ответа:** JSON

**Пример ответа:**
```json
{
  "status": "success",
  "message": "Тест успешно удален"
}
```

**Ошибки:**
- `404 Not Found` — если тест не найден.


### 10. Обновление вопроса в тесте

**Метод:** `PUT`

**Эндпоинт:** `/api/v1/tests/{testId}/questions/{questionId}`

**Описание:** Обновляет информацию о вопросе в тесте.

**Параметры запроса:**
- `testId` (обязательный, integer) — идентификатор теста.
- `questionId` (обязательный, integer) — идентификатор вопроса.

**Параметры запроса (в теле запроса):**
- `text` (необязательный, string) — новый текст вопроса.
- `type` (необязательный, string) — новый тип вопроса.

**Формат ответа:** JSON

**Пример ответа:**
```json
{
  "status": "success",
  "data": {
    "id": 1,
    "text": "Обновленный текст вопроса о InfoCube?",
    "type": "open"
  }
}
```

**Ошибки:**
- `400 Bad Request` — если отсутствуют данные для обновления.
- `404 Not Found` — если тест или вопрос не найден.


### 11. Удаление вопроса из теста

**Метод:** `DELETE`

**Эндпоинт:** `/api/v1/tests/{testId}/questions/{questionId}`

**Описание:** Удаляет вопрос из теста.

**Параметры запроса:**
- `testId` (обязательный, integer) — идентификатор теста.
- `questionId` (обязательный, integer) — идентификатор вопроса.

**Формат ответа:** JSON

**Пример ответа:**
```json
{
  "status": "success",
  "message": "Вопрос успешно удален"
}
```

**Ошибки:**
- `404 Not Found` — если тест или вопрос не найден.
