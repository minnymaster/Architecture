# Лабораторная работа №4. Проектирование REST API

---

## 1. Проектные решения

### 1. Ресурсо-ориентированный дизайн

**Решение:**
Использовать ресурсо-ориентированный подход для проектирования API, где каждый тип данных представлен как отдельный ресурс.

**Описание:**
- Эндпоинты построены на основе ресурсов: `/tests`, `/tests/{id}`, `/tests/{id}/questions`.
- Используются существительные во множественном числе для обозначения ресурсов.

**Обоснование:**
- Соответствует REST-стандартам, делает API интуитивно понятным и предсказуемым.
- Упрощает поддержку и расширение API.


### 2. Стандартные HTTP-методы

**Решение:**
Использовать стандартные HTTP-методы для выполнения CRUD-операций.

**Описание:**
- `GET` — для получения данных.
- `POST` — для создания данных.
- `PUT` — для полного обновления данных.
- `DELETE` — для удаления данных.

**Обоснование:**
- Стандартные методы обеспечивают совместимость с большинством клиентов и серверов.
- Позволяют легко понимать назначение каждого эндпоинта.



### 3. Версионирование API

**Решение:**
Использовать версионирование API через префикс в URL.

**Описание:**
- Версия API указывается в пути URL: `/api/v1/tests`.

**Обоснование:**
- Позволяет поддерживать несколько версий API одновременно.
- Обеспечивает обратную совместимость при внесении изменений.



### 4. Формат данных JSON

**Решение:**
Использовать JSON для обмена данными между клиентом и сервером.

**Описание:**
- Все запросы и ответы используют формат JSON.
- Заголовок `Content-Type: application/json` обязателен для всех запросов и ответов.

**Обоснование:**
- JSON является стандартным форматом для REST API, легко читается и обрабатывается.
- Поддерживается большинством современных языков и фреймворков.


### 5. Стандартизированные сообщения об ошибках

**Решение:**
Использовать стандартный формат для сообщений об ошибках.

**Описание:**
- Все ошибки возвращаются в формате JSON.
- Структура ошибки включает код ошибки, сообщение и дополнительные данные.

**Пример:**
```json
{
  "status": "error",
  "error": {
    "code": 404,
    "message": "Тест не найден",
    "details": "Тест с ID 123 не существует."
  }
}
```

**Обоснование:**
- Стандартизация ошибок упрощает их обработку на стороне клиента.
- Позволяет клиенту легко определять тип ошибки и предпринимать соответствующие действия.


### 6. Валидация данных

**Решение:**
Валидировать входные данные на сервере.

**Описание:**
- Проверка наличия обязательных полей.
- Проверка типов данных.

**Пример:**
```javascript
if (!title || !description || !category) {
  return res.status(400).json({
    status: "error",
    error: {
      code: 400,
      message: "Некорректные данные",
      details: "Отсутствуют обязательные поля: title, description, category."
    }
  });
}
```

**Обоснование:**
- Обеспечивает целостность данных и предотвращает ошибки на сервере.
- Улучшает качество данных, сохраняемых в системе.


### 7. Разделение логики на маршруты и контроллеры

**Решение:**
Разделять логику приложения на маршруты и контроллеры.

**Описание:**
- Маршруты (`routes/tests.js`) отвечают за определение эндпоинтов.
- Контроллеры (`controllers/testController.js`) содержат логику обработки запросов.

**Обоснование:**
- Улучшает структуру кода и делает его более модульным.
- Упрощает поддержку и тестирование приложения.


### 8. Логирование и мониторинг

**Решение:**
Использовать логирование и мониторинг для отслеживания работы API.

**Описание:**
- Логирование запросов и ошибок.
- Мониторинг производительности и доступности API.

**Пример:**
```javascript
app.use((req, res, next) => {
  console.log(`${req.method} ${req.url}`);
  next();
});
```

**Обоснование:**
- Позволяет оперативно выявлять и устранять проблемы.
- Улучшает понимание работы системы и помогает в анализе производительности.

## 2. Реализация API

### 1. Получение списка тестов

**Метод:** `GET`

**Эндпоинт:** `/api/v1/tests`

**Описание:** Возвращает список всех доступных тестов.

**Параметры запроса:** Нет.

**Формат ответа:** JSON

**Пример ответа:**
```json
{
  "status": "success",
  "data": [
    {
      "id": 1,
      "title": "Тест по SAP BW",
      "description": "Тест на знание основ SAP BW",
      "category": "SAP BW"
    },
    {
      "id": 2,
      "title": "Тест по ETL",
      "description": "Тест на знание процессов ETL",
      "category": "ETL"
    }
  ]
}
```


### 2. Получение информации о конкретном тесте

**Метод:** `GET`

**Эндпоинт:** `/api/v1/tests/{id}`

**Описание:** Возвращает информацию о конкретном тесте по его идентификатору.

**Параметры запроса:**
- `id` (обязательный, integer) — идентификатор теста.

**Формат ответа:** JSON

**Пример ответа:**
```json
{
  "status": "success",
  "data": {
    "id": 1,
    "title": "Тест по SAP BW",
    "description": "Тест на знание основ SAP BW",
    "category": "SAP BW"
  }
}
```

**Ошибки:**
- `404 Not Found` — если тест не найден.

**Пример ошибки:**
```json
{
  "status": "error",
  "error": {
    "code": 404,
    "message": "Тест не найден",
    "details": "Тест с ID 123 не существует."
  }
}
```


### 3. Создание нового теста

**Метод:** `POST`

**Эндпоинт:** `/api/v1/tests`

**Описание:** Создает новый тест.

**Параметры запроса (в теле запроса):**
- `title` (обязательный, string) — название теста.
- `description` (обязательный, string) — описание теста.
- `category` (обязательный, string) — категория теста.

**Формат запроса:** JSON

**Пример запроса:**
```json
{
  "title": "Тест по SAP HANA",
  "description": "Тест на знание основ SAP HANA",
  "category": "SAP HANA"
}
```

**Формат ответа:** JSON

**Пример ответа:**
```json
{
  "status": "success",
  "data": {
    "id": 3,
    "title": "Тест по SAP HANA",
    "description": "Тест на знание основ SAP HANA",
    "category": "SAP HANA"
  }
}
```

**Ошибки:**
- `400 Bad Request` — если отсутствуют обязательные поля.

**Пример ошибки:**
```json
{
  "status": "error",
  "error": {
    "code": 400,
    "message": "Некорректные данные",
    "details": "Отсутствуют обязательные поля: title."
  }
}
```


### 4. Получение списка вопросов для теста

**Метод:** `GET`

**Эндпоинт:** `/api/v1/tests/{id}/questions`

**Описание:** Возвращает список вопросов для конкретного теста.

**Параметры запроса:**
- `id` (обязательный, integer) — идентификатор теста.

**Формат ответа:** JSON

**Пример ответа:**
```json
{
  "status": "success",
  "data": [
    {
      "id": 1,
      "text": "Что такое InfoCube?",
      "type": "open"
    },
    {
      "id": 2,
      "text": "Какие типы данных используются в SAP BW?",
      "type": "multiple-choice",
      "options": ["Master Data", "Transaction Data", "Metadata", "All of the above"]
    }
  ]
}
```

**Ошибки:**
- `404 Not Found` — если тест не найден.


### 5. Отправка ответов на тест

**Метод:** `POST`

**Эндпоинт:** `/api/v1/tests/{id}/submit`

**Описание:** Принимает ответы пользователя на вопросы теста и сохраняет их для дальнейшей обработки.

**Параметры запроса:**
- `id` (обязательный, integer) — идентификатор теста.

**Формат запроса:** JSON

**Пример запроса:**
```json
{
  "answers": [
    {
      "question_id": 1,
      "answer": "InfoCube — это многомерная структура данных в SAP BW."
    },
    {
      "question_id": 2,
      "answer": ["Master Data", "Transaction Data"]
    }
  ]
}
```

**Формат ответа:** JSON

**Пример ответа:**
```json
{
  "status": "success",
  "message": "Ответы успешно сохранены"
}
```

**Ошибки:**
- `400 Bad Request` — если поле `answers` отсутствует или не является массивом.
- `404 Not Found` — если тест не найден.

**Пример ошибки:**
```json
{
  "status": "error",
  "error": {
    "code": 400,
    "message": "Некорректные данные",
    "details": "Поле answers должно быть массивом."
  }
}
```


### 6. Получение результатов теста

**Метод:** `GET`

**Эндпоинт:** `/api/v1/tests/{id}/results`

**Описание:** Возвращает результаты прохождения теста для конкретного пользователя.

**Параметры запроса:**
- `id` (обязательный, integer) — идентификатор теста.

**Формат ответа:** JSON

**Пример ответа:**

```json
  "status": "success",
  "data": {
    "results": [
      {
        "question_id": 1,

        "feedback": "Не совсем точно, попробуйте еще раз."
      }
    ],
    "total_score": 8
  }
}
```

**Ошибки:**
- `404 Not Found` — если тест не найден.

### 8. Обновление теста

**Метод:** `PUT`

**Эндпоинт:** `/api/v1/tests/{id}`

**Описание:** Обновляет информацию о тесте.

**Параметры запроса:**
- `id` (обязательный, integer) — идентификатор теста.

**Параметры запроса (в теле запроса):**
- `title` (необязательный, string) — новое название теста.
- `description` (необязательный, string) — новое описание теста.
- `category` (необязательный, string) — новая категория теста.

**Формат ответа:** JSON

**Пример ответа:**
```json
{
  "status": "success",
  "data": {
    "id": 1,
    "title": "Обновленный тест по SAP BW",
    "description": "Обновленное описание теста на знание основ SAP BW",
    "category": "SAP BW"
  }
}
```

**Ошибки:**
- `400 Bad Request` — если отсутствуют данные для обновления.
- `404 Not Found` — если тест не найден.

**Описание:** Удаляет тест по его идентификатору.

```json
  }
```

**Ошибки:**

### Примеры для остальных эндпоинтов

Для остальных эндпоинтов (`PUT`, `DELETE`, `/questions`, `/submit`, `/results`) тесты составляются аналогично. Ниже приведены краткие описания.

---

### 4. Обновление теста

**Тестируемое API:** `/api/v1/tests/{id}`

**Метод:** `PUT`

#### Тесты:
1. Обновление существующего теста с корректными данными.
2. Обновление несуществующего теста.

---

### 5. Удаление теста

**Тестируемое API:** `/api/v1/tests/{id}`

**Метод:** `DELETE`

#### Тесты:
1. Удаление существующего теста.
2. Удаление несуществующего теста.

---

### 6. Получение списка вопросов для теста

**Тестируемое API:** `/api/v1/tests/{id}/questions`

**Метод:** `GET`

#### Тесты:
1. Получение списка вопросов для существующего теста.
2. Получение списка вопросов для несуществующего теста.

---

### 7. Отправка ответов на тест

**Тестируемое API:** `/api/v1/tests/{id}/submit`

**Метод:** `POST`

#### Тесты:
1. Отправка ответов на существующий тест с корректными данными.
2. Отправка ответов на несуществующий тест.

---

### 8. Получение результатов теста

**Тестируемое API:** `/api/v1/tests/{id}/results`

**Метод:** `GET`

#### Тесты:
1. Получение результатов для существующего теста.
2. Получение результатов для несуществующего теста.

---

### 9. Создание нового вопроса для теста

**Тестируемое API:** `/api/v1/tests/{id}/questions`

**Метод:** `POST`

#### Тесты:
1. Создание нового вопроса для существующего теста с корректными данными.
2. Создание нового вопроса для несуществующего теста.

---

### 10. Обновление вопроса в тесте

**Тестируемое API:** `/api/v1/tests/{testId}/questions/{questionId}`

**Метод:** `PUT`

#### Тесты:
1. Обновление существующего вопроса в тесте с корректными данными.
2. Обновление несуществующего вопроса в тесте.

---

### 11. Удаление вопроса из теста

**Тестируемое API:** `/api/v1/tests/{testId}/questions/{questionId}`

**Метод:** `DELETE`

#### Тесты:
1. Удаление существующего вопроса из теста.
2. Удаление несуществующего вопроса из теста.

---
